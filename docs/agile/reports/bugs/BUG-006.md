# Bug Report: BUG-006 - Background and FAB scroll with content on small screens (broken scroll containment)

**Status:** ✅ Resolved (2026-06-26)
**Severity:** 🟠 Medium (Layout / UX)
**Affected Sprint:** [sprint-07](../../sprint-backlogs/sprint-07.md)
**Fixed in:** `0.14.1`

## 📖 Description
บนหน้าจอที่ **เล็กเกินไป** เมื่อ scroll ลง เนื้อหา (content) เลื่อนพร้อมกับ **พื้นหลัง (background)** และ **ปุ่ม FAB** ด้วย แทนที่จะเป็นเฉพาะเนื้อหาเลื่อน ทำให้:
- **สีพื้นหลังถูกตัด** (background ไม่เต็มจอเมื่อเลื่อน)
- **ปุ่ม FAB ไม่ float** — แทนที่จะลอยอยู่กับที่ มันเลื่อนตาม content ไปจนไปอยู่กลางจอ

พบบนหน้า **ข้อมูลผู้เล่น (Player-Info)** และน่าจะเกิดกับหน้า DOM อื่นที่ใช้ pattern การ scroll เดียวกัน

**Steps to reproduce:**
1. เปิดหน้า Player-Info บนหน้าจอเล็ก (เนื้อหายาวเกินความสูง viewport)
2. Scroll ลง
3. **ผลที่เกิด:** background และปุ่ม FAB เลื่อนตาม content (FAB ไปจบกลางจอ, พื้นหลังถูกตัด)
4. **ผลที่ควรเป็น:** เฉพาะ content เลื่อนภายใน container; background เต็มจอเสมอ; FAB ลอย (float) อยู่กับที่

## 🖼 Visual Reference
![Background and FAB scrolling with content](assets/bug-006-scroll-containment.png)

## 🛠 Proposed Fix
- ให้ **scroll เกิดภายใน inner content container** (มี `overflow-y:auto` + ความสูงจำกัด) แทนที่จะให้ทั้งหน้า/`body` เลื่อน
- ตั้ง **background** ที่ระดับ container/`fixed` ให้เต็ม viewport เสมอ ไม่เลื่อนตาม content
- ตั้งปุ่ม **FAB** เป็น `position: fixed` (หรือ sticky เทียบ viewport) เพื่อให้ลอยจริง ไม่ผูกกับ scroll ของ content
- ตรวจ pattern เดียวกันกับหน้า DOM อื่น (Hub/Profile/Leaderboard) ให้สอดคล้องกับ [TD-E6-05](../../01-product-backlog.md)

## 🔎 Root Cause
ต้นเหตุของอาการ "จอถูกดันลงมา / มีพื้นที่ว่างเกินจน scroll" คือ **section ของแต่ละหน้าใส่ `min-height: 100vh` เอง** ซ้อนอยู่ใน `#app` ที่ก็เป็น `min-height: 100vh` + `padding: 24px` อยู่แล้ว เมื่อ `box-sizing: border-box` ทั่วทั้งโปรเจกต์:
- `#app` = สูง `100vh` พอดี (padding อยู่ข้างใน)
- `.player-info-screen` (section) = `min-height: 100vh` **แต่ถูกวางใน content area ของ `#app` ที่เหลือ `100vh − 48px`** → section ล้นออกไป **48px** → ทั้ง document เลื่อน ทั้งที่เนื้อหาจริงสั้นกว่าจอ
- พอ document เลื่อน → พื้นหลัง gradient (อยู่บน `body`) ถูกตัด และ FAB (`position: absolute` ที่ไม่มี positioned ancestor) เลื่อนตาม document หายไป

**สรุป:** ความสูงเท่าจอควรกำหนดที่ระดับ shell/`body` ที่เดียว ไม่ใช่ใส่ซ้ำในทุก `<section>`

## ✅ Resolution (2026-06-26, verified)
CSS-only ใน `public/style.css` แก้ 3 จุด:
1. **section height ซ้อนกัน:** เอา `min-height: 100vh` ออกจากกลุ่มหน้าการ์ด `.login-screen, .signup-screen, .player-info-screen` — ปล่อยให้ `#app` (ซึ่งยังเป็น `min-height: 100vh` + `place-items: center`) เป็นตัวเดียวที่ให้ความสูงเท่าจอและจัดกึ่งกลางการ์ด → ไม่มี 48px ที่ล้น, ไม่มีการดันจอ
2. **พื้นหลังเลื่อนตาม content:** ย้าย gradient ไปไว้บน **fixed pseudo-element** `body::before` (`position: fixed; inset: 0; z-index: -1` + `background-attachment: fixed`) แทนที่จะอยู่บน `body` ตรงๆ — gradient จึง **pin กับ viewport ไม่เลื่อนตามการ scroll** (เลี่ยง `background-attachment: fixed` บน `body` ที่ไม่เสถียรบน iOS Safari); `body` เหลือสีพื้น `#8be298` เป็น fallback; ซ่อน pseudo ในมินิเกมด้วย `body.game-mode::before { display: none }`
3. **FAB ลอยจริง:** `.hub-clean-test-menu` เปลี่ยน `position: absolute` → `position: fixed` (class นี้ใช้เฉพาะหน้า Player-Info — ตรวจแล้วใน `src/` — ไม่กระทบหน้าอื่น)

> หมายเหตุ: หน้า full-bleed ที่ใช้ layout คนละแบบ (`.landing-screen`, `.checkin-summary-screen`) ยัง **คง** `min-height: 100vh/svh` ไว้เพราะ section เป็นเจ้าของความสูงเอง (grid `fr` / overlay) — ไม่เข้าเคสนี้
