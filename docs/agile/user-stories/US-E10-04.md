## 📖 Description
**ในฐานะ** ผู้ดูแลระบบ/ผู้วิจัยที่ใช้ popup ส่งออก CSV ในหน้า Player-Info
**ฉันต้องการ** เลือก **กลุ่มผู้เล่น** ที่จะส่งออกได้ (นอกจาก "ข้อมูลของ" และ "ประเภทข้อมูล" เดิม)
**เพื่อให้** ดึงข้อมูลแยกรายกลุ่มทดสอบ (เช่น เฉพาะหางดง / เฉพาะท่าศาลา) ไปวิเคราะห์ได้เลย
ไม่ต้อง export ทั้งหมดแล้วมากรองเองทีหลัง

เพิ่มส่วนที่ 3 ใน popup export (`src/ui/export-options-popup.js`):

```
ข้อมูลของ :        ○ ผู้เล่นคนนี้   ○ ผู้เล่นทั้งหมด
ประเภทข้อมูล :     ☑ ข้อมูลผู้เล่น  ☐ ข้อมูลการเล่นเกม  ☐ ประวัติการเล่นรายวัน
กลุ่มผู้เล่น :      ○ ...ตาม user_group_tag...          ← ใหม่
```

**และ:** popup ตอนนี้เนื้อหาเริ่มยาว เมื่อเพิ่มกลุ่มเข้าไปจะยิ่งสูง — ต้องใส่ **scroll view**
ให้ส่วนรายการเลื่อนได้ ไม่ให้ popup สูงเกินจอ (ปุ่มยกเลิก/ส่งออกต้องกดถึงเสมอ)

---

## 🗄 ข้อมูลกลุ่ม (จาก DB — ผ่าน MCP)

ตาราง `user_group_tag` — เอา `tag_name` มาแสดง, ใช้ `GRPID` เป็นค่า filter:

| GRPID | tag_name | ความหมาย |
|---|---|---|
| `UNTAGGED` | ไม่มี | ผู้เล่นที่ยังไม่ถูก tag |
| `HD01` | หางดง | |
| `TS01` | ท่าศาลา | |

⚠️ **อย่า hardcode รายการกลุ่ม** — กลุ่มเพิ่มได้ ต้อง query `user_group_tag` มาสร้างตัวเลือกตอนเปิด popup
(แนวเดียวกับที่ [US-E10-02](US-E10-02.md) ทำกับ leaderboard) เพิ่ม `db.getGroupTags()` ใน
`src/core/database.js` ถ้ายังไม่มี

⚠️ **กลุ่มผูกกับผู้เล่นผ่าน `user_game_profile_data.GRPID`** (ไม่ได้อยู่บน `user_data` โดยตรง) และตาราง
นั้น **ไม่มี `UNIQUE(hn)`** — ต้องใช้ "แถวล่าสุดชนะ" (`DISTINCT ON (hn) ORDER BY created_at DESC, id DESC`)
เหมือนที่ [US-E10-02](US-E10-02.md) migration ทำ ไม่งั้นผู้เล่นที่มีหลายแถวจะนับกลุ่มผิด

---

## ❓ ต้องเคลียร์กับ owner ก่อนลงมือ
1. **"กลุ่มผู้เล่น" ทำงานร่วมกับ "ข้อมูลของ" ยังไง?** ตอนนี้ "ข้อมูลของ" มี ผู้เล่นคนนี้ / ทุกคน
   ถ้าเลือก "ผู้เล่นคนนี้" แล้วยังเลือกกลุ่มได้อยู่ไหม (คนเดียวก็อยู่กลุ่มเดียว การเลือกกลุ่มจะซ้ำซ้อน) —
   น่าจะให้ "กลุ่มผู้เล่น" มีผลเฉพาะเมื่อ "ผู้เล่นทั้งหมด" หรือทำให้สองส่วนนี้ exclusive กัน
2. **เลือกได้กลุ่มเดียวหรือหลายกลุ่ม?** (radio = ทีละกลุ่ม / checkbox = หลายกลุ่ม + "ทุกกลุ่ม")
3. **`UNTAGGED` เป็นตัวเลือกในลิสต์ไหม** หรือใช้แค่ "ทุกกลุ่ม" ก็พอ
4. **ค่า default** — "ทุกกลุ่ม" (พฤติกรรมเดิม export ทั้งหมด) หรือกลุ่มของผู้เล่นที่กำลังดู

---

## 🔀 จุดที่ต้อง filter จริง (สำคัญ — มีหลายเส้นทาง)
Export **ไม่ได้ดึงจาก client ตรง ๆ** แต่เรียก edge function → RPC ฝั่ง server:
- `get_player_export_rows`, `get_game_export_rows`, `get_game_history_csv_export_rows`
  (รีโป `mci-database-edge-functions`, `read-database/actions.ts` → `exportRowsVia`)
- ทั้ง 3 ตัวรับแค่ `p_hn` / `p_offset` / `p_limit` ตอนนี้

ดังนั้นการ filter กลุ่มต้อง**ทำฝั่ง server** — เพิ่ม `p_grpid` (nullable) ให้ RPC ทั้ง 3 แล้ว JOIN
`user_game_profile_data` กรอง เหมือนที่ทำกับ `get_leaderboard_page` ⚠️ **อย่าให้ client กรองเอง
หลังดึงมาทั้งหมด** เพราะ export อาจมีหลายพันแถว (game export ~2,387 แถว) และเสีย paging ที่มีอยู่

⚠️ **ระวัง overload trap ซ้ำ** — ถ้าเพิ่ม argument ใหม่ให้ RPC ที่มีอยู่ด้วย `CREATE OR REPLACE`
ต้อง `DROP` ตัว signature เก่าทิ้ง ไม่งั้นเกิด overload กำกวม (เจอมาแล้วทั้งใน US-E10-02 และ export เดิม)

## ✅ Acceptance Criteria
1. [ ] popup export มีส่วน "กลุ่มผู้เล่น :" เพิ่มจาก "ข้อมูลของ" และ "ประเภทข้อมูล"
2. [ ] ตัวเลือกกลุ่มมาจาก `user_group_tag` (query จริง ไม่ hardcode) แสดง `tag_name` filter ด้วย `GRPID`
3. [ ] เลือกกลุ่มแล้ว CSV ที่ได้มีเฉพาะผู้เล่นในกลุ่มนั้น — ตรวจกับข้อมูลจริง (หางดง 20 / ท่าศาลา 31)
4. [ ] filter ทำฝั่ง server (RPC รับ `p_grpid`) ไม่ใช่ client กรองหลังดึงทั้งหมด — paging ไม่พัง
5. [ ] popup มี **scroll view** ในส่วนรายการ — ไม่สูงเกินจอ ปุ่มยกเลิก/ส่งออกกดถึงเสมอ (จอเล็ก + แนวนอน)
6. [ ] CSV มี**คอลัมน์กลุ่ม** (`GRPID` และ/หรือ `tag_name`) เพื่อใช้แยกตอนวิเคราะห์ — **ปิด [US-E10-01](US-E10-01.md) AC#4 ที่ descope ไว้**
7. [ ] พฤติกรรมเดิมไม่ regress — ไม่เลือกกลุ่ม/เลือก "ทุกกลุ่ม" = export เหมือนเดิม (US-E9-05)
8. [ ] A11y เดิมคงอยู่ (radio/checkbox จริง, `aria-labelledby`, ปิดด้วยปุ่ม/backdrop/Escape)
