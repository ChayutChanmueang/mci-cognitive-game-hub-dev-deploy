# User Story: US-E4-04 - ระบบจัดเก็บบันทึกการเล่นซ้ำพฤติกรรม (Replay Event Logging)

**Status:** ✅ Done (Implemented and tested)
**Epic:** [E4: Data Tracking & Analytics (Supabase)](../../01-product-backlog.md)
**Owner:** TBD

---

## 📖 Description
**ในฐานะ** แพทย์/นักวิจัยทางคลินิก
**ฉันต้องการ** ให้ระบบบันทึกลำดับเหตุการณ์และพฤติกรรมการเล่นในมินิเกมอย่างละเอียดทีละขั้นตอน (Step-by-step)
**เพื่อให้** สามารถดึงข้อมูลความเคลื่อนไหวของผู้ป่วยมาจำลองพฤติกรรมย้อนหลัง (Replay) หรือประเมินประสิทธิภาพเชิงลึกได้แม่นยำ

---

## ✅ Acceptance Criteria
1. [x] ระบบจัดเก็บข้อมูลเหตุการณ์เชิงโต้ตอบ (Interactive Events) เช่น เวลาเริ่มต้น จังหวะการกดเลือกคำตอบ การจับคู่ผิด/ถูก
2. [x] การจัดเก็บบันทึกใช้ระบบบัฟเฟอร์ (Buffering System) ในฝั่ง Client เพื่อบันทึกพฤติกรรมระหว่างเล่น ก่อนจะนำส่งเขียนลงฐานข้อมูลพร้อมกันเมื่อจบเกม เพื่อลด Overhead ในการเชื่อมต่อ API
3. [x] ข้อมูลบันทึกประวัติรองรับการส่งออกผลลัพธ์ผ่าน CSV ออกมารวมยอดความถูกต้อง (total_correct / total_wrong) และวิเคราะห์รายขั้นตอนได้

---

## 🛠 Technical Tasks
- [x] พัฒนา `replay-log-buffer.js` เพื่อทำโครงสร้างคิวและจัดเก็บการดำเนินการระหว่างเล่นเกมแบบ Local
- [x] ออกแบบตารางใน Supabase และเขียน SQL Schema สำหรับเก็บ Replay Event Logs
- [x] ปรับปรุงตรรกะในแต่ละมินิเกมให้ส่งเหตุการณ์เข้ามาบันทึกในบัฟเฟอร์ในแต่ละขั้นตอนหลัก
- [x] บูรณาการและพัฒนาคีย์วิเคราะห์คำนวณใน API ส่งออกรายงาน CSV (`player-csv-export.js`)
