## 📖 Description
**ในฐานะ** ผู้วิจัย/ผู้ดูแลระบบ (Researcher/Admin)
**ฉันต้องการ** ให้ Leaderboard ภายในเกมแสดงเฉพาะผู้เล่นในกลุ่มทดสอบที่มี Tag ตรงกับผู้เล่นปัจจุบัน
**เพื่อให้** การเปรียบเทียบคะแนนเกิดขึ้นภายในกลุ่มเดียวกัน ง่ายต่อการเปรียบเทียบผลในแต่ละกลุ่มทดสอบ

---

## ✅ Acceptance Criteria
1. [x] Leaderboard แสดงเฉพาะผู้เล่นที่มี `GRPID` เดียวกับผู้เล่นที่ล็อกอินอยู่
2. [x] อันดับ (rank) ของผู้เล่นปัจจุบันคำนวณ **ภายในกลุ่ม** — `get_user_rank` กรองด้วยกฎเดียวกับ `get_leaderboard_page`
3. [x] ~~ผู้เล่นที่ไม่มี Tag เห็นเฉพาะผู้เล่นที่ไม่มี Tag ด้วยกัน~~ → **owner กลับด้าน (2026-07-20):** `UNTAGGED` **เห็นทุกกลุ่ม** เพราะ `GRPID` ส่วนใหญ่เป็นของ admin ไว้ตรวจว่าใครอยู่อันดับเท่าไหร่ (ดู §Decisions)
4. [x] Pagination (`offset`/`limit`) ยังทำงานถูกต้องหลังกรอง — `total_players` นับจากชุดที่กรองแล้ว
5. [x] เส้นทาง fallback ทั้งหมด (Edge Function → RPC → client query) กรองตามกลุ่มเหมือนกัน
6. [x] ทดสอบข้ามกลุ่มบนข้อมูลจริง — `HD01` 20 คน / `TS01` 31 คน / `UNTAGGED` 51 คน (ทั้งหมด)

---

## 🔀 Decisions
- **`UNTAGGED` เห็นทุกกลุ่ม (กลับด้านจาก AC#3 เดิม).** AC#3 ตอนเขียนเดายังไม่ได้ จึงระบุให้ถามก่อน — owner
  ยืนยัน 2026-07-20 ว่า `GRPID` ส่วนใหญ่เป็นของ admin ไว้ตรวจอันดับ ดังนั้น `UNTAGGED` = มุมมองเห็นทั้งหมด
  ไม่ใช่กลุ่ม default ที่แยกออกมา ผู้เล่นที่ไม่มีแถวใน `user_game_profile_data` เลยก็นับเป็น `UNTAGGED`
- **กลุ่ม resolve ฝั่ง server จาก `hn` ไม่รับ `GRPID` จาก client.** RPC เป็น `SECURITY DEFINER` เรียกได้ด้วย
  anon key — ถ้ารับ `GRPID` ตรง ๆ ใครก็ขอดูกลุ่มไหนก็ได้
- **ship แยกจาก US-E10-01.** schema (`user_group_tag` + `user_game_profile_data.GRPID`) owner สร้างไว้แล้ว
  งานที่ยังเหลือใน US-E10-01 คือ **เครื่องมือ admin สำหรับ tag ผู้เล่น** ตอนนี้ยัง tag ผ่าน SQL เท่านั้น

## ⚠️ ยังไม่ได้ทำ
- **ยังไม่ได้ทดสอบบนเครื่องจริง** — ยืนยันที่ระดับ SQL + HTTP endpoint เท่านั้น ยังไม่ได้เปิดหน้า Leaderboard
  ในเกมเพื่อดูหัวข้อ "ชุมชนพัฒนาสมองหางดง" กับตา
- **สถานะกลุ่มที่มีคนน้อย** — ยังไม่ได้ออกแบบเพิ่ม ถ้ากลุ่มมีผู้เล่นคนเดียวจะเห็นรายชื่อแถวเดียว (ไม่ error)
- `getUserGroup` ถ้า RPC หายจะ fallback เป็น `UNTAGGED` เงียบ ๆ ซึ่งหน้าตาเหมือน "ผู้เล่นไม่มี tag จริง ๆ" —
  ควรแยกให้ error ดังกว่านี้ ไม่งั้น deploy ที่ขาดจะดูเหมือนฟีเจอร์ทำงานปกติแต่ไม่กรอง
