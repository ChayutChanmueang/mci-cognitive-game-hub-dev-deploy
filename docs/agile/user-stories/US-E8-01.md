## 📖 Description
**ในฐานะ** ผู้เล่นที่ลงทะเบียนในโปรแกรม 14 วัน
**ฉันต้องการ** ให้ต้นคิดดี (progression tree ในหน้าเช็คอิน) แสดง **ชนิดต้นไม้ที่แตกต่างกันต่อผู้เล่น** และคงที่ตลอดโปรแกรม
**เพื่อให้** รู้สึกเป็นส่วนตัว ไม่เบื่อเมื่อเห็นต้นไม้แบบเดียวกันทุกคน และสอดคล้องกับ art หลายชนิดที่เตรียมไว้ (a / b / c / d)

---

## 🐛 Problem (ปัจจุบัน — v1.0.0)
- `getTreeImagePath()` ใน `checkin-summary-screen.js` ชี้ไปที่ asset เดียว: `/assets/checkin-popup/tree_0${stage}.png` (ชนิดต้นไม้เดียวทั้งระบบ)
- `user_game_profile_data` ในโค้ดยัง **ไม่ได้อ่าน/เขียน** คอลัมน์ `tree_type`
- Art ชนิด a–d ถูกจัดเก็บแล้วที่ `public/assets/checkin-popup/{a|b|c|d}/tree_{type}_{NN}.png` แต่ยังไม่ถูกใช้งาน
- **ผู้เล่น v1.0.0 ที่เริ่มโปรแกรมไปแล้ว:** แถวใน `user_game_profile_data` ที่สร้างก่อน feature นี้มักมี `tree_type = NULL` (หรือยังไม่ถูกตั้งค่า) — ต้องมี **lazy backfill** ตอนเข้าเกม ไม่ใช่แค่ fallback ชั่วคราวบน UI

## 🗄 Database Schema (`user_game_profile_data`)

```sql
create table public.user_game_profile_data (
  id bigint generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  program bigint null default '2'::bigint,
  hn text null,
  tree_type text null,
  constraint game_hub_data_pkey primary key (id),
  constraint game_hub_data_hn_fkey foreign KEY (hn) references user_data (hn) on delete CASCADE,
  constraint user_game_hub_data_program_fkey foreign KEY (program) references game_level_preset_list (id)
) TABLESPACE pg_default;
```

> `tree_type` ไม่มี database default: signup ต้องสุ่มจาก `game_tree_list` และส่งค่าใน `INSERT`; แถวเก่าหรือการ insert ที่ไม่ส่งค่าจะเป็น `NULL` และเข้าสู่ lazy-backfill flow ตอนเปิด Game Hub

| Column | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `tree_type` | `text` | `'a'` | ชนิดต้นคิดดีของผู้เล่น — FK แบบ soft ไป `game_tree_list.id` (เช่น `a`, `b`, `c`, `d`) |

### `game_tree_list` — รายการชนิดต้นไม้ที่ระบบสุ่มได้

```sql
create table public.game_tree_list (
  id text not null,
  created_at timestamp with time zone not null default now(),
  name character varying null,
  constraint game_tree_list_pkey primary key (id)
) TABLESPACE pg_default;
```

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | `text` PK | รหัสชนิดต้นไม้ — ตรงกับโฟลเดอร์ asset และ `user_game_profile_data.tree_type` (เช่น `a`, `b`, `c`, `d`) |
| `name` | `varchar` | ชื่อแสดงผล (ภาษาไทย/อังกฤษ) — ใช้ใน admin/tooling ได้ในอนาคต |

**Seed ข้อมูล production (2026-07-08)** — แทนที่ตัวอย่างเดิม; `name` ยังเป็น `null` ทุกแถว
```sql
insert into public.game_tree_list (id, created_at, name) values
  ('a', '2026-07-08 05:15:22.322362+00', null),
  ('b', '2026-07-08 05:15:29.272548+00', null),
  ('c', '2026-07-08 05:15:39.760009+00', null),
  ('d', '2026-07-08 05:15:46.406401+00', null);
```

> แหล่งความจริงของรายการที่สุ่มได้ = **`game_tree_list`** (ไม่ hardcode ใน client) — เพิ่มชนิดใหม่ในอนาคตได้โดย seed ตาราง + เพิ่ม asset โฟลเดอร์

### 🔄 Migration — ผู้เล่น v1.0.0 ที่เริ่มไปแล้ว

เกมปัจจุบันเป็น **v1.0.0** จึงมีผู้เล่นที่ลงทะเบียนและเล่นก่อน deploy คอลัมน์ `tree_type` — ณ 2026-07-08 มี **17 profile** (id 59–75) ที่ **`tree_type IS NULL` ทั้งหมด** ดูรายละเอียดใน [Production Snapshot](#-production-snapshot-2026-07-08)

| สถานการณ์ | พฤติกรรมที่ต้องการ |
| :--- | :--- |
| Profile ใหม่ (signup หลัง v1.1.0) | สุ่มจาก `game_tree_list` ตอน `INSERT` |
| Profile เก่า, `tree_type` มีค่าแล้ว | ใช้ค่าเดิม ไม่สุ่มใหม่ |
| Profile เก่า, `tree_type IS NULL` หรือ `''` | **Lazy backfill** ตอนโหลด profile: สุ่มจาก `game_tree_list` → `UPDATE` → ใช้ค่านั้นต่อ |

**จุดที่เรียก backfill (แนะนำ):** `ensureUserGameProfileTreeType({ hn })` ใน `database.js` — เรียกจาก login success / โหลด Game Hub ก่อนแสดง check-in popup
