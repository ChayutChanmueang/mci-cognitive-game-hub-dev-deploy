## 📖 Description
**ในฐานะ** แอดมิน/ทีมวิจัย
**ฉันต้องการ** สคริปต์ CLI สำหรับ **แก้ไข ID ผู้เล่น** (ใน DB คือคอลัมน์ `hn`) ที่ลงทะเบียนผิด (เช่น ใส่เบอร์โทรแทน ID)
**เพื่อให้** แก้ข้อมูลได้อย่างปลอดภัยแบบเดียวกับ `delete-user.js` โดยไม่ต้องแก้ DB มือ ๆ

---

## 🐛 Problem (จากการลงพื้นที่ — v1.0.0)
- มีผู้เล่นบางคน **ใส่ ID ผิด** (ใส่เบอร์โทรศัพท์แทน)
- ต้องการเครื่องมือ **update `hn`** ใน database พร้อม cascade ไปตารางที่อ้างอิง
- มี `delete-user.js` เป็นต้นแบบแล้ว — ต้องการ **`update-user-hn.js`** (หรือชื่อเทียบเท่า) ในรูปแบบเดียวกัน

---

## 📝 คำศัพท์ — Frontend vs Backend

| ชั้น | ชื่อที่ใช้ | ตัวอย่างในโค้ด |
| --- | --- | --- |
| **Frontend (UI)** | **ID** / Patient ID | `#patient-id-input`, `patient_login_id`, label `ID{hn}` ในหน้า Sign-up |
| **Backend (DB / CLI)** | **`hn`** | คอลัมน์ `user_data.hn`, FK ใน `user_game_history.hn`, flag CLI `--from-hn` / `--to-hn` |

> ในเอกสารนี้และสคริปต์ CLI ใช้ **`hn`** ตาม schema/database; เวลาอธิบายกับทีมหรือผู้ใช้ UI ให้เข้าใจว่า **ID ที่ผู้เล่นกรอก = `hn` ในระบบหลังบ้าน** เป็นค่าเดียวกัน

## ✅ Acceptance Criteria
1. [ ] มีสคริปต์ CLI `update-user-hn.js` (หรือชื่อที่สอดคล้อง) ที่ root โปรเจกต์ — pattern เดียวกับ [delete-user.js](../../../delete-user.js)
2. [ ] รองรับ: `--from-hn <OLD>` `--to-hn <NEW>` พร้อม `--dry-run` และ `--help`
3. [ ] อัปเดต `hn` ใน **`user_data`** และตารางที่ FK อ้างอิง (`user_game_history`, `game_user_log`, `game_replay_log`, `user_game_profile_data` ฯลฯ) **อย่างสอดคล้อง** — atomic หรือ transaction
4. [ ] ตรวจสอบก่อนอัปเดต: `to-hn` **ยังไม่มี** ในระบบ, `from-hn` **มีอยู่**
5. [ ] `--dry-run` แสดงแผน + จำนวนแถวที่จะเปลี่ยน โดยไม่เขียน DB
6. [ ] ใช้ **service_role key** เท่านั้น (ไม่ใช้ anon key) — เอกสารใน header comment
7. [ ] อัปเดต `docs/software/03-data-schema.md` ระบุขั้นตอนแก้ ID/`hn` และ mapping Frontend **ID** ↔ Backend **`hn`**
