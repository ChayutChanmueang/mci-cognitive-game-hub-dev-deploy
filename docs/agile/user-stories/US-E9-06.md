## 📖 Description
**ในฐานะ** ผู้เล่นสูงอายุ
**ฉันต้องการ** ให้หน้าจอไม่ดับระหว่างเล่นเกม แม้เครื่องจะตั้งค่าพักหน้าจอไว้สั้น

## 🐛 Problem (จากการลงพื้นที่ — v1.0.0)
- บางเครื่องตั้งค่า **พักหน้าจอ (screen timeout) น้อย**
- ระหว่างเล่นเกม **หน้าจอดับ** ทำให้ขาดจังหวะและสับสน

1. [x] ระหว่างเล่น **มินิเกม** (Phaser scene active) หน้าจอ **ไม่ดับ** ตาม timeout ปกติของระบบ
2. [x] ระหว่างดู **วิดีโอละครสั้น** / check-in video หน้าจอไม่ดับ (ถ้า browser รองรับ)

4. [x] ถ้า browser/OS **ไม่รองรับ** Screen Wake Lock API → degrade gracefully (ไม่ error) *(ไม่ได้แสดงคำแนะนำ timeout — เป็น optional ใน AC)*
5. [x] ทดสอบบน Android จริง (รวมเครื่องที่ตั้ง timeout สั้น) — ✅ เจ้าของงานยืนยัน 2026-07-10: หน้าจอไม่ดับระหว่างเล่น และกลับมา dim ได้ตามปกติเมื่อออกมาหน้า Game Hub (ยืนยัน AC3)

## 📝 Implementation Notes
- Commit `7e982e1` เพิ่ม `acquire()` แต่ **ไม่เคยเรียก `release()`** เลย → wake lock ค้างหลังออกจากมินิเกม (ขัด AC3, กินแบตเตอรี่) และ `acquire()` ถูกเรียก **ก่อน** `destroyActiveGame()` ทำให้เกิด race ตอนสลับเกม — แก้แล้วโดยย้าย `acquire()` ไปหลัง `startGame()` สำเร็จ และใส่ `release()` ใน `destroyActiveGame()`
- Manager เปลี่ยนจาก flag `_isPhaserActive` (boolean) เป็น `Set` ของ owner เพื่อให้ minigame และ video ถือ lock พร้อมกันได้โดยไม่ปล่อยทับกัน

### 🔑 Root cause จากการทดสอบบนเครื่องจริง (หน้าจอยังดับ)
- **Screen Wake Lock API เป็น `[SecureContext]` ตาม W3C spec** → ถ้าเปิดแอปผ่าน `http://` (เช่น nginx test VM ผ่าน LAN IP) `navigator.wakeLock` จะเป็น `undefined` ทั้งหมด
- โค้ดเดิม `return` เงียบ ๆ เมื่อ `!isSupported` → ไม่มี log ไม่มีสัญญาณใด ๆ แยกไม่ออกระหว่าง "ทำงานอยู่" กับ "ไม่ทำอะไรเลย"
- **แก้:** (1) ใส่ fallback เล่นวิดีโอเงียบวนลูป (`wake-lock-video-source.js`, data URI ~7.5KB) ซึ่งไม่ต้องใช้ secure context; (2) `getStatus()` + `window.__wakeLock` สำหรับ debug บนเครื่องจริง; (3) warn ชัดเจนเมื่อ origin ไม่ secure
- **วิธีแก้ที่ถูกต้องที่สุดคือ serve ผ่าน HTTPS** — fallback เป็นแค่ตาข่ายรองรับ (Chromium ให้ video wake lock เฉพาะวิดีโอที่ "มองเห็นได้" จึงตั้งขนาด 64×64 `opacity:0.01` แทนการซ่อน)
- ตรวจสอบบนเครื่องจริง: เปิด console แล้วเรียก `__wakeLock.getStatus()` ระหว่างอยู่ในเกม → ถ้า `secureContext: false` แปลว่าสาเหตุคือ origin ไม่ใช่ HTTPS

### ⚠️ งานติดตาม (follow-up)
ยังไม่ได้ตรวจว่าเครื่องจริงใช้ strategy ไหน (`__wakeLock.getStatus().strategy`) ถ้าเป็น `video-fallback` แสดงว่า origin ยังไม่ใช่ HTTPS และตอนนี้พึ่ง heuristic ของ Chromium (ให้ video wake lock เฉพาะวิดีโอที่ "มองเห็นได้") ซึ่งอาจเปลี่ยนใน Chrome รุ่นถัดไปโดยที่โค้ดเราไม่ได้แก้อะไรเลย → **ควร serve ผ่าน HTTPS เพื่อให้ใช้ Wake Lock API ตัวจริง**
